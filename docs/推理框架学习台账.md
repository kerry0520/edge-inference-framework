## 主线地图

用户要求扩大工作并完成目标后，新的性能阶段先测同一次真实请求的模型执行、读取和采样，再按证据选择快路径。本轮准备的一个主要抽象是[只读采样是否需要复制分数](手机推理主线：采样为什么可以不复制分数.md)：通用状态需要允许惩罚/过滤修改副本，但纯 greedy 只读，可以尝试避免副本；mixed 最后一步为 greedy 并不意味着能跳过前面的处理。源码核对还发现旧 `decode_tps` 不含采样时间，因此采样优化要用独立完整请求 wall 时间验收。固定发布版 3.6.1 的适配与最新上游已有实现严格区分，尚未声明收益，学习理解状态待确认。

2026-10-02 继续工程后的下一项主线材料是[为什么要比较完整 logits](手机推理主线：为什么要比较完整logits.md)。主要抽象是模型输出与采样之间的边界：模型给所有候选打分，sampler 才选择 token。通过“最高候选相同、其他分数不同”的三候选例子说明文字一致不足以证明计算一致。本轮准备在手机比较固定输入序列的完整分数，不重复教学 prefill/decode。实验完成和学习者掌握仍分开记录；目前已整理，理解未确认。

本轮完整分数实验已完成：两长度、两版本、四种缓存状态共 16 次；主 agent 独立读取全部 12,154,880 个分数并核对每步输入、NaN/Inf、误差和产物哈希。修复版所有状态与正确冷启动基线完全一致，原版切换回缓存出现误差。工程结论是限定配置下的数值正确性，学习者是否理解“模型输出和采样的边界”仍未确认。验收工具另补自动关联检查，能够拒绝被改错的 C++ 计数、丢失的官方计数及变化的生命周期哈希；无需学习这些脚本内部。

一条请求有两层问题：

1. **生成层**：文字怎样变成 token ID，模型怎样从这些 ID 逐步生成回答。
2. **执行层**：模型的一次计算怎样由 MNN 安排到手机 CPU 上的具体算子。

先顺着请求走完生成层，再进入执行层。缓存修复、W4/W8 内核和性能实验是后续案例，不是理解主线的前置条件。nano-vLLM 已学过的分块和调度只作对照，不重复从零讲。
