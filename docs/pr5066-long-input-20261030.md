## 全部相邻配对

- 128 token：进程 0/1：1.29%；进程 3/2：1.03%
- 256 token：进程 5/4：1.83%；进程 6/7：1.47%

精确身份与调频记录见 public-results.json；对外JSON按字段白名单导出，不含设备序列号、IP或主机绝对路径。

已补充更长的多 chunk 输入对照：128 / 256 / 512 token，对应 chunk32 下的 4 / 8 / 16 个块。输入来自同一段自然技术文本经该模型 MNN tokenizer 编码后的固定前缀。

在小米11、Qwen3-0.6B、CPU单线程、low precision 下，先完成独立的6进程/24请求正确性验证，12对完整f32输出及生成token、文本和公开状态逐项一致。随后重新运行12个独立进程/48请求的计时；每进程4请求，首请求单列，后三次取中位数，再汇总每侧2个独立进程。长度顺序为128ABBA、256BAAB、512ABBA，未并入旧33/65 token样本。

这组固定样本的描述性中位数差异约为1–3%，不据此作统计显著性或普遍提速结论。

每组相邻开关对照的耗时下降（均保留）：

- 128 token：进程 0/1：1.29%；进程 3/2：1.03%
- 256 token：进程 5/4：1.83%；进程 6/7：1.47%
- 512 token：进程 8/9：1.72%；进程 11/10：3.25%

正式计时中的48次请求均核对token、文本和公开状态；每个进程最后一题额外核对完整f32，共12次完整f32比较。指标覆盖response及最终logits映射/等待，不含调用方reset、分词、结果写盘或HTTP/ADB传输；每次仅生成3 token，因此这里反映prefill占主导的请求，不是单独prefill内核或长decode收益。load加首题也不作为端到端启动耗时。CPU 温度实际范围：开始 34.2–37.1℃，结束 47.1–54.4℃。

补充说明：第一批长输入资格验证在512 token关闭侧结束时达到51.4℃，超过事先设定的50℃上限，原批次按失败保留、未进入计时。查看本轮速度前，将结束温度纳入上限一次性调整为55℃后，以新批次完整重跑6个资格进程和12个正式进程；开始CPU31–40℃、电池29–33℃、电源/调频及频率上限检查均保持原约定。55℃仅是本次操作纳入条件，不代表安全界限或无降频证明。

实际测量沿用已核对与v6生产代码token等价的v5库及新长输入测试程序，并非PR头提交的精确ELF。本结论仅限上述模型、设备和三个固定输入，所有进程明细、配对结果及失败批次均已保留。


加载加首题并非所有配对都改善，因此不宣称冷加载或首题普遍提速；上表保留全部原始值。完整response计时不包含调用者reset、分词、校验和写盘等范围外工作。
