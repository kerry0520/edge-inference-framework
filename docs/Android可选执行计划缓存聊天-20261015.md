# 从聊天开关到手机执行计划

这一课主要学一个关系：**应用层决定发送哪些消息，引擎决定怎样执行这些消息对应的token。** 这两个职责分开，才能更换执行策略而不改变对话含义。

## 用户第二次提问时，手机收到什么

假设第一次问“我是小王”，模型回答“你好，小王”；第二次问“我叫什么”。完整历史模式发送的不是孤零零的第二句话，而是前三条消息：用户第一句、模型第一答、用户第二句。手机套聊天模板、编码成token，再重置上一题的计算状态，重新处理这份完整输入。

因此模型能看见前文，同时本轮的KV复用token计数仍为0。这并不矛盾：前文作为消息重新输入了，没有直接沿用上一题算出的KV。

这次的新开关允许保留同一个模型实例已经准备好的主干执行计划。它不会删掉消息，也不会替你记忆新内容。长输入的非末块通过主干，最后块和decode通过完整Module。短输入不需要省略中间块的输出，因此仍直接执行完整模型。

## 三个命令，三种不同职责

| 操作 | 消息历史 | 当前上下文KV | 模型与执行计划 |
|---|---|---|---|
|继续提问|保留，并添加新问题|完整历史模式每题重置并重算|模型保留，长输入可命中计划|
|`/new`|清空|重置|模型和可用计划仍保留|
|`/exit`|结束本次会话|随模型实例清理|销毁模型、释放其计划与依赖|

预算超限属于拒绝执行，不应偷偷删历史凑长度。没有确认完整回答时，本地也不能假装回答已经成功，并拿半截文字继续下一题。

## 沿项目入口读三层

1. [phone_chat.py](../scripts/android/phone_chat.py)解析开关并选择入口。没有新开关时走既有路径；新开关只允许完整历史模式与统计一起使用。
2. [phone_chat_plan.py](../scripts/android/phone_chat_plan.py)固定已验配置、检查构建身份，把消息交给现有流式会话逻辑，并核对手机返回的计划状态。它不实现Attention或量化计算。
3. [phone_chat_plan_worker.cpp](../apps/android/phone_chat_plan_worker.cpp)驻留一个Llm，把收到的消息编码、reset、调用response；response里面才进入前一课的Module/Attention/算子执行。worker新增的是入口协议和计数，不是重新发明一套模型计算。

完整链条是：电脑消息列表 → 手机聊天模板/token IDs → reset并调用response → 分块prefill/主干计划 → 最后prefill与decode输出 → 流式字节 → 完整final确认 → 本地历史提交。

## 为什么接入口还要重新验收

前一课的固定ID测试证明了执行优化在限定条件下正确，却没有证明聊天入口一定用了正确的库和配置。若这里仍用chunk0，根本不会进入分块优化；若消息历史被丢掉，输出含义也变了。

这次验收重点是配置到达手机、自然多轮输入确实包含历史、长输入冷建后命中、/new与短输入不误删计划、预算拒绝不改历史，以及真正退出后计划登记为空。它不重复宣称新的完整logits证明或性能百分比。

当前工程状态与已验范围见[入口阶段续做](../evidence/plan-cache-chat-20261015/README.md)。新入口已经完成下述限定场景验收；“能打印文字”之外，消息历史、实际路由和正常退出也分别检查。本课已提供，理解待学习者反馈。

## 在当前电脑上使用

手机无线ADB在线、固定模型与本机构建已配置时，在项目目录运行：

```powershell
python scripts/android/phone_chat.py --mode full --stats --prefill-plan-cache --max-new-tokens 64
```

输入问题并回车，回答会逐段出现。`/history`查看已确认的消息，`/new`开始新对话，`/stats`查看最近一次统计，`/exit`正常退出。

统计中的“复用token”指KV；这个模式重新计算完整历史，因此该数值为0是正常的。新增的“执行计划”一行才说明主干计划是首次准备、已经复用，还是本题太短而直接完整执行。

默认部署预算为输入模板token＋生成预算合计512。超过预算会拒绝本题，保留已确认历史，可以用`/new`开始新对话；不会自动截断前文。这个上限是当前已验入口的部署范围，不是宣称模型自身最多512token。不开新开关仍走原来的默认入口。

本机自然会话配对回归已通过：6轮输入长度13/61/87/109/13/61，开启与关闭优化的文字、token和结束状态一致。候选长请求冷建一次、命中三次，短请求走完整模型；预算拒绝和/new没有误删计划。实际命令行入口亦已验收，工程原件见续做。

本课工程验收已完成：实际不带手机地址的命令行自动连接，40token输入得到32token流式回答，显示“首次准备”；命令行、原生worker均正常退出，计划登记为空。另有同库开关配对6轮回答一致、/new与预算拒绝保计划等证据；不是新一轮完整logits/性能实验。
