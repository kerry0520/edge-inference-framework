# 已有模型接入示例与兼容矩阵

核对日期：2026-10-29。适用于本机项目当前 `--model` 实现；使用已部署资源，不负责下载、转换或自动安装。本文给出可以照做的已有组合示例；新设备、新模型需要另行接入和验收。

## 先运行一次已有模型

在 PowerShell 切到项目目录，避免相对路径落在 `C:\Windows\System32`：

```powershell
cd "C:\path\to\edge-inference-framework"
python scripts/android/phone_chat.py --list-models
python scripts/android/phone_chat.py --model qwen3-0.6b --prompt "用一句话介绍你自己" --max-new-tokens 32
```

列表不连接手机。真正启动需要手机已配对、无线 ADB 可用，以及本机受验程序和手机既有模型资源完整。省略 `--serial` 会走原有自动发现；需要指定时，在启动命令后追加 `--serial 192.168.5.4:当前端口`，地址取手机无线调试主页实际值。

切换到已有1.7B组合，只换注册名：

```powershell
python scripts/android/phone_chat.py --model qwen3-1.7b --prompt "解释什么是推理框架" --max-new-tokens 64
```

省略 `--prompt` 即进入交互模式，使用 `/history` 查看已确认历史、`/new` 开始新对话、`/exit` 退出并清理。一次只启动一个入口，先正常退出上一模型再切换。

## 打开网页入口

```powershell
python scripts/android/phone_http.py --model qwen3-1.7b --port 8080
```

看到 `Phone HTTP ready: http://127.0.0.1:8080` 后，在电脑浏览器打开该地址。切换0.6B时将注册名改成 `qwen3-0.6b`。在启动服务的终端按 Ctrl+C 正常收尾。端口占用时使用另一个空闲端口；服务会先保留实际监听端口，再加载模型。

网页与HTTP服务在电脑，模型计算在手机。服务只监听电脑回环地址，不提供手机浏览器直接访问或公网多用户服务。HTTP是一个共享对话，计算请求串行；新请求需要当前 session_id/revision，旧页面应刷新状态，不自动重放未知结果。

## 当前兼容矩阵

| 项目 | qwen3-0.6b | qwen3-1.7b |
|---|---|---|
| 设备范围 | 既有 Mi11 / M2011K2C / ARM64 组合，稳定设备序列号校验 | 同左 |
| 模型资源 | `/data/local/tmp/MNN/Qwen3-0.6B-MNN-modelscope`；使用原默认模型身份hook | `/data/local/tmp/MNN/Qwen3-1.7B-MNN-cc0cae045f11`；严格匹配固定1.7B profile |
| 本地声明 | catalog中的原默认资源选择 | `configs/models/qwen3-1.7b-mnn.json` |
| Session策略 | 原 PlanCacheSession；保留历史已验主干计划路径 | 原 LargerModelSession / BaselinePlanSession；关闭该主干计划路径 |
| 后端与线程 | CPU，4线程，low精度，chunk32，greedy | 同左 |
| 跨轮历史 | 保存消息，每轮完整历史重算；reuse_kv=false | 同左 |
| 单次生成的KV | 正常使用；与跨轮复用是不同概念 | 同左 |
| 部署预算 | 输入token总数＋本次生成预算不超过512，可调低 | 同左 |
| 默认生成预算 | CLI 64；不是必须生成满64 | 同左 |
| 资源与native身份 | 本机构建记录、程序、源码、模型身份匹配；加载前与关闭后检查模型 | 同左，四个固定模型文件的大小/SHA及profile内容也必须匹配 |
| #5066新优化 | 不自动启用 | 不自动启用 |

512是此部署入口的安全预算，不是模型架构最大上下文。文字长度与token数不相等；多轮历史、模板和生成预留都参与预算计算。超预算拒绝后不提交新历史，可 `/new` 再问。`--max-context-tokens 384` 可收紧预算，不能借选择已有模型把它提高到512以上。

1.7B profile固定来源为 `MNN/Qwen3-1.7B-MNN` revision `cc0cae045f11c525fba613066ce7c54da03ac4dd`，绑定 `llm.mnn`、`llm.mnn.weight`、`llm_config.json`、`tokenizer.txt`。权重文件约1.23 GB只表示磁盘文件大小，不能据此当作运行RAM需求。现有手机可运行这两种组合；本文未提供其它手机的最低RAM保证、长上下文内存上限或任意8GB设备兼容结论。

## 参数冲突与失败行为

- CLI显式 `--model` 不能同时使用KV/query模式、stats、stats-build-tag、prefill-plan-cache、plan-profile或adb-path等旧实验路由。默认full模式可以省略；不加 `--model` 的旧路由保持原行为。
- HTTP `--model` 与 `--model-profile` 互斥。1.7B不允许plan-profile或adb-path覆盖固定native路径；HTTP 0.6B保留原运行包profile能力，但此示例只用默认已部署组合。
- 未知注册名、非法profile、越界预算和资源身份不符会拒绝启动或请求，不静默切换为另一个模型。HTTP未知名/模型profile互斥在绑定端口前拒绝；部分后端参数冲突在预留端口后、连接ADB前拒绝，并释放端口。
- 传输中断或结果未知时保留记录，先核对原状态；不要重复发送同一题来掩盖失败。清理必须核验目标worker身份，不能杀掉任意手机进程。

## 加入新组合前需要做什么

1. 明确目标：模型家族、量化格式、输入输出、模板、tokenizer、上下文预算和目标设备；确认当前MNN与worker支持这些能力。
2. 成套固定资源：记录模型来源revision、图、权重、tokenizer及模板配置的大小和SHA。不能只替换权重，也不能把可任意填写的目录当作完成接入。
3. 独立核对设备与程序：ABI、CPU/后端能力、worker/native构建身份、存储和实测内存余量。现有固定序列号守卫不能直接删除来宣称支持其它手机。
4. 先选安全执行策略：优先普通完整执行；只有结构、KV共享与生命周期都通过验收，才允许启用派生主干等候选。
5. 让同一聊天/HTTP逻辑使用新的资源适配，避免复制请求循环。验证错误早停、资源变更拒绝、无静默回退、旧组合不受影响。
6. 真实设备依次验证加载、首轮、多轮、预算拒绝后历史不变、new/reset、关闭和资源前后身份。再验CLI与HTTP/SSE实际入口；需要性能结论时另冻测量协议。
7. 更新catalog、兼容矩阵和复现记录，注明已验与未验。离线fixture通过不能替代新模型或第二台手机实测。

## 现在是否要引入任意模型schema

目前不需要开放任意模型JSON。两个注册项已经共享选择入口、请求循环和HTTP适配；1.7B保留专用profile的主要原因是严格资源身份与执行策略准入，尚没有第三种真实组合证明哪些字段应该成为通用契约。

下一次确有新组合时，先从本节步骤抽出重复的“资源清单验证”和“设备能力检查”，保持模型资源、设备能力、执行策略三者分离。目录、线程、后端和优化开关不应混成一份可任意覆盖的JSON。只有具备第二组使用者及相应错误验收后，再替换已有专用适配；不要为字段整齐而提前扩大接入范围。
