# 手机地址变了，为什么不等于换了一台手机

这一节只理解“连接地址”和“设备身份”的区别，不需要记ADB命令细节。它位于推理请求开始前：电脑先找到正确的手机，才能把问题交给手机模型执行。

## 把它接回一次请求

正式入口先在本地校验运行包；随后找到设备并核身份，再检查模型、部署程序、加载模型、发送问题。模板与Tokenizer、prefill/decode、MNN图执行和量化算子都在连接成功之后。

IP和端口像本次的收件地址，会随网络与无线调试重新分配。稳定硬件身份用于确认是哪台手机；模型与程序身份用于确认将运行什么。旧代码仅按记住的IP筛选，就可能在手机明明在线时报告找不到设备。修改地址也不能让一个未验程序自动变成已验版本。

## 这次改动的职责

先看ADB已有在线连接，包括USB和已配对无线服务；必要时再读取mDNS提供的连接地址。对候选实际读取型号和稳定硬件身份，确认是项目目标手机。已核的高优先级连接可用时，就不继续探测低优先级地址。两条同优先级连接都报告目标身份时，要求显式选择，避免随意挑一个。

候选来自设备列表和连接服务，探测数与单条超时有上限；不会扫描局域网、自动签配对码、断开其他设备或关闭ADB服务。显式指定连接地址仍可使用，聊天入口会继续核对目标硬件。

发现、身份核验、启动准备和真实推理分别记录。启动检查通过只说明包与设备条件具备；只有实际请求结束、回答与状态有效、退出清理确认，才能说这次聊天流程通过。

## 本轮结果

旧逻辑的只读复现已确认：手机使用新IP及在线无线服务，旧自动选择仍失败；同一时间显式连接身份核验成功。新自动选择与独立12模块客户端启动检查均已通过。随后正式聊天也在没有--serial的情况下完成一题，并确认程序退出、转发移除及计划释放；输入/输出ID、文字字节和结束状态与旧参考一致，模型文件保持不变。83项相关测试中82通过、1为既有权限跳过，独立原件复核通过。

本轮4token仅作连接回归，输出因预算截断，不用于评价完整回答质量；日常聊天默认64token。mDNS回退路径在模拟测试覆盖，本轮手机已经在线，未人为断开来制造回退。原件见工程记录（本地原件：`results/android/automatic-phone-selection-20261017/阶段续做.md`）。

这项改动不改变模型、量化算法、主干执行计划或受审程序。已提供解释，理解待反馈；框架主线仍从[自学手册](项目自学与独立演示手册-20261017.md)学习。

## 本机ADB日志权限问题的适用说明

自动发现依赖可用的电脑ADB服务和既有配对。这次宿主后台服务写adb.log被拒绝，使用foreground模式完成恢复，没有修改系统权限或研究手机无线开关。该宿主限制的原因尚未确定，不能归因用户改配置，也不属于本轮自动发现修复的范围。

若本机再次显示相同错误且5037没有ADB服务，可在项目目录的一个PowerShell终端运行以下已验证方式，保持该终端打开，再在另一终端运行原聊天命令：

```powershell
.\tools\android\platform-tools\adb.exe -L tcp:localhost:5037 server nodaemon
```

已有服务正常时沿用现有服务，不需要先kill-server。此命令只提供电脑ADB服务，不启动模型。
