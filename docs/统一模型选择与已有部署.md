# 统一选择已有手机模型

本次增加的是已有部署的选择方式，不会自动下载、转换模型或适配新手机。已有设备身份、native 构建和模型资源校验继续生效。计算仍在手机；电脑负责命令行或网页交互。

## 查看和启动

在项目根目录执行：

```powershell
python scripts/android/phone_chat.py --list-models
python scripts/android/phone_chat.py --model qwen3-0.6b --prompt "你好" --max-new-tokens 32
python scripts/android/phone_chat.py --model qwen3-1.7b --prompt "你好" --max-new-tokens 32
python scripts/android/phone_http.py --model qwen3-1.7b --port 8080
```

需要手工指定无线连接时可加 `--serial IP:PORT`。列表无需手机连接；启动会验证当前设备和既有模型，不会自行安装文件。`--model` 与 HTTP 原 `--model-profile` 互斥。HTTP 1.7B 不能再组合 `--plan-profile` 或 `--adb-path`；CLI 显式模型选择不能组合 KV/query/stats/plan 等旧实验路由。预算为输入及生成合计最多512 token，不代表模型最大上下文。

不加 `--model` 的原命令行为保持原样：HTTP 默认仍是原0.6B PlanCacheSession；原 `phone_chat.py` 根据自己的mode/stats等参数分派，不能把它误认为HTTP默认工厂。原显式 `--model-profile configs/models/qwen3-1.7b-mnn.json` 仍可使用。

## 两个声明对应什么

| 注册名 | 资源选择 | 执行策略 | 范围 |
|---|---|---|---|
| qwen3-0.6b | 既有默认 Session 的模型身份hook | 原 PlanCacheSession，完整历史重算及历史受验计划路径 | 既有固定Mi11/native组合 |
| qwen3-1.7b | configs/models/qwen3-1.7b-mnn.json，严格匹配固定来源、图/权重/词表/模板配置 | 原 LargerModelSession，关闭主干计划候选，完整历史重算 | 既有固定Mi11/native候选组合 |

这里没有默认为项目worker启用新的上游PR #5066。两种模型各自保留原策略，统一选择不意味着可任意交换资源或后端。1.7B 文件profile仍由原严格解析器验证并在start前重读；加载前和close后使用同一个模型身份hook。模型选择失败不会自动降级到另一个模型。

## 希望理解的关系

模型声明决定“运行哪一套已知资源和策略”；Session 管加载、请求、历史和收尾；MNN 执行图负责实际计算。这三件事分开后，添加新选择不必复制一套聊天逻辑。但新模型要正式加入仍需资源配套检查、设备/程序能力和真实问答、拒绝、重置、清理验收，不能只加一个名称。
