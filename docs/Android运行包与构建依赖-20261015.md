# 运行包为什么可以离开构建目录

这一课主要理解：**构建模型执行程序需要的材料，不等于每次运行都需要的文件。**

## 手机真正运行什么

目前的链条是：电脑Python客户端 → ADB传输与端口转发 → 手机上的worker可执行文件 → 已放在手机里的模型文件。

worker已经静态链接MNN。也就是链接时把需要的MNN实现放进了可执行文件，手机不必再寻找电脑那份`libMNN.a`。本轮检查确认，它仍依赖Android系统库，也仍需要另外的模型权重；静态链接不意味着连模型数据也装进了程序。

NDK、头文件、Ninja参数和旧archive用于构建与追溯，不应为了运行一次聊天就强迫它们保留在原文件夹。上一轮为了严密绑定实验来源，把这些都放进了启动校验；本轮把它们分开。

## 配置解决位置，固定身份解决版本

新运行包保存已验worker、两份小源码快照，以及profile、runtime-build和provenance说明。profile里的路径相对运行包目录，所以可以整体移动。

但是，“配置说这份程序是对的”不等于程序真的对。若允许修改程序后，把profile的SHA也跟着改掉，完整性校验就没有固定依据了。因此代码中保留已验版本的身份登记，运行时重新计算包里文件的SHA并匹配登记；profile不能自己批准一个新版本。

这不是对所有软件的通用签名机制，只是本项目固定验收版本的身份绑定。重新编译得到不同ELF时，需要新的构建与验收记录，不能靠改一个SHA沿用旧结论。

## 为什么不再依赖旧实验目录

导出时，程序仍调用旧严格resolver，确认源文件、库、构建命令和结果都属于已验构建，才允许复制。导出后，运行路径只读取包内文件及当前客户端，不再去翻旧build/results/header/archive。

| 时机 | 主要职责 |
|---|---|
|导出运行包|从完整构建证据确认这份程序的来源，再生成包|
|运行包启动|确认包内容仍为已验版本、配置在限定范围，然后部署|
|从源码重建|准备固定MNN源码、补丁、NDK和编译选项，生成并重新验收产物|

三个动作不能混称“一键复现”。本轮主要交付前两个；客户端Python和已配置手机仍是前置条件，模型也不随包分发。

## 源码入口

- [phone_plan_profile.py](../scripts/android/phone_plan_profile.py)：`export_bundle`和`resolve_profile`区分导出与运行校验，`resolve_adb_path`选择工具位置。
- [phone_chat_plan.py](../scripts/android/phone_chat_plan.py)：给每个Session设置包内worker/manifest/source路径，启动前再核一次；没有profile仍用原路径。
- [phone_chat.py](../scripts/android/phone_chat.py)：新增显式profile参数，仍要求完整历史模式与计划复用开关。消息历史、KV重置与执行计划逻辑沿上一课。

## 怎样验证“真的搬走了”

不能只把路径字符串换一下就算完成。测试将包放进含中文、空格的新目录，并封住旧构建目录的读取；如果程序仍要找历史archive或header，就立即失败。另检查篡改文件、自己改SHA、缺文件和越界路径会在连接手机前被拒绝。

本机离线门禁已通过；真实符号链接因Windows权限跳过，模拟越界分支通过。搬移后的手机请求与原入口的比较仍按独立实机验收记录判定，见[本阶段续做](../results/android/portable-plan-profile-20261015/阶段续做.md)。已提供本课，理解待反馈。


## 使用方式

先在已有完整验收构建的电脑导出一次（目标目录须尚不存在）：

```powershell
python scripts/android/phone_plan_profile.py export --output build/phone-runtime-v1
```

`phone-runtime-v1`可以整体搬到其他目录。导出包含约87MiB的已验程序及小型源码/身份说明，不包含模型权重、静态库或NDK。

在当前客户端项目中指定搬移后的profile即可：

```powershell
python scripts/android/phone_chat.py --mode full --stats --prefill-plan-cache --plan-profile "新的目录/profile.json"
```

如ADB不在项目工具目录或PATH，可再给`--adb-path "工具目录/adb.exe"`。profile是自动生成的已验配置，不需要手工修改SHA；更换模型或设备不是改这里一个路径就算验收。

这个导出命令仍需要原构建的完整证据；运行包启动才不需要。别在还没导出并验证前清理原材料，本轮也没有清理既有文件。

当前验收状态：原入口与搬移运行包各三次实机请求，输入/输出token、回答文字、状态和计划路由一致；搬移入口的主机Python读取守卫未发现旧构建读取或旧解析器调用。独立客户端目录再提问一次，成功加载和流式输出，客户端与手机进程均正常退出。该目录在启动前没有build/results，运行时只新增自己的会话记录；这证明当前客户端路径可以独立，不等于另一台电脑或其他型号也已验收。全部原始采集在本地保存，公开仓库提供[精简验收](https://github.com/kerry0520/edge-inference-framework/tree/main/evidence/portable-plan-profile-20261015)。

原控制入口曾因电脑保存退出日志失败而记录stopped_with_error；已经补读原日志核对，没有修改旧状态，也没有重问手机。随后修复日志采集，不影响模型计算。本阶段不新增性能提升或完整logits结论。

## 这一步在最终项目中的位置

此前我们验证了“怎样复用执行计划”，本次解决“怎样把这个已验能力交给聊天入口运行”。一次请求仍是文字→token→LLM安排prefill/decode→MNN执行→token转文字。profile只在请求开始前选择并验证要部署的程序，不参与算子数学，也不是KV缓存。

例如把包从A目录搬到B目录，应该只改变启动时的profile路径；同一问题仍得到相同输入token与输出，而无需把旧静态库和编译日志也搬过去。这个关系就是本课要学会的内容，日志复制命令无需作为必学知识。

下一层交付仍未完成：固定MNN源码和依赖的干净全量构建、另一台电脑安装验证、其他手机或模型的适配。现有导出器需要已验本机构建，公开仓库也不分发模型或原生程序。
