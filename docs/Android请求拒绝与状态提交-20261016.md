# 请求被拒绝后，为什么还能接着聊天

这节抓住一个概念：**成功回答才提交对话状态。** 你学过nano-vLLM，这里的token化、prefill/decode可以直接衔接；重点是框架入口怎样处理“这一轮没有完成”。

假设你已经完成两轮对话，电脑保存着`用户1、回答1、用户2、回答2`。现在再提交一段过长文字。程序先把已有消息与新问题组成待处理请求，但暂时不把这段文字写进已确认历史。手机套用模板并分词，发现“输入token数＋预留生成数”超过当前部署预算512，就返回拒绝。

拒绝之后的已确认历史仍是前面四条消息。你再问“请简短总结”，这个问题接在原来的两轮之后；过长的那段文字没有混进上下文。这里没有悄悄删掉早期消息来凑预算。

| 状态 | 成功回答后 | 超预算拒绝后 | `/new`后 |
|---|---|---|---|
| 应用消息历史 | 追加这次问题和完整回答 | 保持原样 | 清空 |
| 本模式的KV | 每次按完整历史重新计算 | 此轮不进入infer计算 | 清空当前对话状态 |
| 已准备的主干执行计划 | 长输入可复用 | 保持原样 | 保留，可服务后续长输入 |

注意：预算拒绝不是“手机完全没做事”。为了知道实际输入token数，它已经执行模板处理和分词；但当前worker在调用`infer()`之前就返回，不会为这次被拒绝输入执行模型forward。

## 为什么短输入还要单独验证

本项目按32token分块，长输入的非末块只需主干结果，末块才需要完整输出。输入不超过一个块时，没有非末块，直接走完整图即可。因而`/new`后一个短问题应显示短路径，而下一次足够长的问题仍可命中此前准备的主干计划。这不是短问题把计划删除了，而是它没有用到该路径。

统一验收入口把这些关系放在一次会话里：长输入首次准备→续轮命中→预算拒绝→继续成功→`/new`→短输入完整执行→长输入再次命中。一次顺序走完，才能同时证明拒绝没有破坏历史、`/new`没有误清计划，以及短路径没有污染长路径。

## 怎样运行

先查看离线计划；目标目录要是新目录，不连接手机、不启动模型：

```powershell
python scripts/android/phone_acceptance.py --plan-profile "build/source-runtime-bundle-20261016/手机运行包 空格/profile.json" --output results/local-acceptance-plan
```

确认手机就绪后，加`--run`并换一个新输出目录：

```powershell
python scripts/android/phone_acceptance.py --plan-profile "build/source-runtime-bundle-20261016/手机运行包 空格/profile.json" --output results/local-acceptance-run --run
```

必要时加`--adb-path`或`--serial`。这是使用已验会话类的验收驱动，不是代替互动聊天入口。它会加载一个手机模型进程，执行5个成功请求、1次预期预算拒绝和1次新对话；异常时停止并收尾，不自动重发。完整结果、逐步进度和原始会话写进指定目录。

复核包含预期预算拒绝的记录时，使用`phone_verify_session.py --allow-budget-rejections`；不加该开关仍拒绝把拒绝混入成功场景。开关不会绕过验证：拒绝帧必须满足身份、预算超限、无流式文字、历史不变及时间顺序条件。
