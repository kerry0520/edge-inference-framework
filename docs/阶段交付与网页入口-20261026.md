# 阶段交付：网页请求如何进入手机推理

本轮提供电脑本机网页入口、HTTP/SSE适配层和显式1.7B模型候选选择源码。网页仍由电脑展示，模型计算仍由手机上的既有固定worker完成。公开仓库不包含模型、原生程序、ADB或作者原始设备记录；clone后可先运行离线测试，实际推理需要已有匹配资产。本轮公开整理没有重新连接手机或测量性能。

## 从一个请求理解职责

网页把消息和已确认会话版本交给HTTP服务。服务只接受本机回环地址上的请求，每次只运行一个请求，并核对会话ID与版本，防止旧页面提交到新的对话。适配层把请求交给现有会话；会话再负责文本/token、上下文预算、手机通信与响应确认。手机worker执行prefill/decode，返回文字片段和完整响应；服务通过SSE把片段交给页面。

主要抽象是“已确认会话状态”。收到几个文字片段不等于请求已完成。后端完整响应确认后才推进历史版本；传输中断、写记录失败或客户端未收到结果时，保留相应状态，不自动重放未知结果。重新发送可能产生第二次计算，因而需要使用者先检查已确认历史。

这层封装不改变模型计算：完整历史重算每轮重新编码历史并计算KV；执行计划复用保存的是执行资源，跨轮KV复用保存的是模型中间数据。网页默认采用现有0.6B会话路线，1.7B显式候选使用完整历史重算并关闭主干计划；这里没有接入新的prefill优化候选。

源码入口：[`phone_http.py`](../scripts/android/phone_http.py)处理状态与HTTP；[`phone_http_backend.py`](../scripts/android/phone_http_backend.py)连接既有会话；[`phone_web`](../scripts/android/phone_web/index.html)展示页面；[`phone_model_session.py`](../scripts/android/phone_model_session.py)核对独立模型身份。框架主线继续是消息→token→prefill/decode→MNN图执行→CPU算子→采样。

## 运行入口与前提

从仓库根目录执行帮助或离线测试不需要手机：

```powershell
python -B scripts/android/phone_http.py --help
python -B scripts/android/phone_chat.py --help
$env:PYTHONUTF8 = "1"
python -B -m unittest discover -s tests/android -p "test_*.py" -v
```

在已经准备好固定受验资产的环境中，启动网页入口后访问终端给出的本机地址：

```powershell
python -B scripts/android/phone_http.py
```

启动会先保留实际本机端口，再加载手机后端；非法端口或端口占用在后端构造前失败。`--port 0`可选择可用端口，以终端ready地址为准。启动中断或后端初始化失败会释放监听socket并清理已建立的后端；不同端口的多个服务仍可能分别启动模型，不提供全设备单实例管理。

Windows监听使用排他地址选项，避免默认地址复用允许两个监听器占同一端口；其他平台沿用原策略。[Microsoft选项说明](https://learn.microsoft.com/en-us/windows/win32/winsock/using-so-reuseaddr-and-so-exclusiveaddruse)解释了两种选项的差异。端口预留不表示模型就绪，打印ready前不处理HTTP请求。

默认模型是Qwen3-0.6B。另行安装并核对固定1.7B模型资产后，显式选择：

```powershell
python -B scripts/android/phone_http.py --model-profile configs/models/qwen3-1.7b-mnn.json
```

该profile只允许固定模型目录、来源修订和文件摘要，不能选择另一原生程序或任意后端。1.7B是独立候选模型身份，代码仍标记`admitted_model=False`；启动成功也不使它获得0.6B既有正式模型身份，失败不会回退成0.6B。脚本保留既有固定程序及历史目录依赖，不提供通用设备安装器。设备身份限制已经存在于公开代码/配置，本轮未新增设备序列号，也未验证其他设备。准备流程见[公开开发与验收路线](公开仓库开发与验收路线-20261017.md)及[公开源码构建](从公开源码生成新的手机程序-20261018.md)。

通用CLI仍由[`phone_chat.py`](../scripts/android/phone_chat.py)提供，当前默认完整历史重算。网页启动方式不改变CLI默认行为，也不提供任意模型切换。

## 最新prefill候选：未达到预定提速目标

另一条隔离工程线在固定MNN提交`959640`、Qwen3-0.6B、小米11单CPU线程上评估省输出层与主干复用的组合候选。输入为33/65 token，每请求生成3 token；8个新进程共32题完成完整logits、状态和环境核对。按固定中位数汇总的暖请求耗时分别由320.58降至300.14毫秒（6.38%），536.14降至516.34毫秒（3.69%），四个配对方向一致。预先要求两个长度均至少改善5%，因此本轮目标未达成，候选默认关闭，不提交上游PR，也没有接入此网页。单个RSS对照约增加8.9 MiB，不代表完整内存分布。

汇总方法是每进程3次暖请求取中位数，再对每长度/变体的2个进程结果取中位数；测量的是暖请求完整耗时，不能归因为缓存单项。本文是作者工程记录的精简派生摘要，公开仓库未提供本轮原始设备日志或完整复现实验包，读者不能仅凭本页独立重算这些数值。两批早期采集失败仍保留为inconclusive，未拼接进最终样本。这里不作通用或统计显著加速结论；原有2026-10-15执行计划结果属于另一实现/协议，不能与本轮数值合并。
