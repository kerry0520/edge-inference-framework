# 编译出了程序，下一步交给谁

源码构建生成静态库和手机程序；下一步要在手机上检查这个程序。但当前正式入口只接受明确登记的已验版本，不能把刚编出的文件换进去，仍沿用旧版本的验收结论。

所以需要一份独立的“待验候选”清单，先把即将检查的文件固定下来。它负责交接，不负责宣布程序正确。

## 清单核对什么

调用者先固定所选构建记录的SHA，再读取程序、库、worker源码和helper源码，核对实际文件与该记录的摘要。手机程序头应符合所需的64位小端AArch64 ELF容器，库应有静态归档头；这些是离线能观察的事实。

摘要相符只能说明本次看的是记录所指的字节。它不能证明程序真的由记录里写着的源码编译，也不能证明程序链接了旁边那份库。文件头正确也不能保证程序可以在手机上运行。编译过程和设备运行还需要各自的证据。

## 清单的状态为什么始终待验

构建记录可能写着编译成功，但这是交给本工具的一项声明，不是本工具重新见证了编译。工具只固定候选资产，因此输出仍为pending，并明确要求设备验证，不会生成已验profile或修改生产白名单。

这和MNN运行链的分工相邻但不同：清单在启动前固定要部署的对象；手机真正启动后，才由LLM和MNN执行token、prefill/decode与算子。离线交接成功不能替代后面的真实计算验证。

## 当前验收范围

本阶段已完成：16项单元测试通过，独立审查的10项异常输入都被拒绝。用现有真实程序、库与源码完成prepare和inspect，两次CLI退出均为0；原文件和生产profile均未修改。候选仍为pending，正式运行包入口会拒绝它，不能把两种输入混用。

本阶段没有重新编译、复制大型库或模型、运行手机。本机真实正例来自历史已验构建，只证明资产绑定逻辑；现代新构建格式使用小fixture测试，不能把它写成“新电脑构建已复现”。手机候选执行与验收注册仍是下一阶段。

工程原件见阶段记录（本地原件：`results/android/source-candidate-handoff-20261016/阶段续做.md`），理解待反馈。

## 使用新增交接入口

先准备真实构建记录与它声明的四项文件，父目录需要已经存在，候选输出目录必须全新。调用者把所选记录的外部SHA传入，不由记录自己宣称可信：

```powershell
$manifestHash = (Get-FileHash "构建记录/build.json" -Algorithm SHA256).Hash.ToLower()
python scripts/android/phone_source_candidate.py prepare --manifest "构建记录/build.json" --expected-sha256 $manifestHash --output "构建记录/待验候选"
```

如果实际库、程序或源码位置不同，可以显式给出`--binary`、`--library`、`--worker`、`--helper`；仍须与记录及固定worker/helper摘要相符。路径不能经过符号链接或Windows目录别名，必要时使用真实路径。工具不复制它们，只在新的候选目录写入小型`candidate.json`。

交给下一步前再次检查，仍需外部固定清单SHA：

```powershell
$candidateHash = (Get-FileHash "构建记录/待验候选/candidate.json" -Algorithm SHA256).Hash.ToLower()
python scripts/android/phone_source_candidate.py inspect --candidate "构建记录/待验候选/candidate.json" --expected-sha256 $candidateHash
```

`inspect`重新核对原记录和实际文件，不运行其中的程序。清单固定为`candidate_pending`、`accepted_profile=false`和`build_proof=not_verified`；即使手改状态并重新计算SHA，也不能把它变成已验。它不是`--plan-profile`的输入，也不会接入当前正式聊天入口。下一阶段还需要明确的候选设备验证和结果审查。

两种已知记录格式分别识别：当前源码配方的receipt和历史link-fix receipt；未知或混杂字段会被拒绝。原记录的退出码和编译声明没有被本工具认证，格式支持不等于各格式都已有真实新构建正例。

后续进展：本页描述的交接阶段当时只验过历史receipt。随后已按公开配方从空对象目录得到现代receipt，并完成固定手机的有限生成对照；见[新程序与源码](Android新程序如何证明来自源码-20261016.md)。candidate仍不自动获得正式profile资格。
