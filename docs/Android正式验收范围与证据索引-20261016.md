# Android正式验收范围与证据索引

本页回答：当前交付程序究竟验过什么，哪些结论只能留在历史实验版本。它是既有证据的统一入口；本次整理没有调用手机、运行模型或新增性能结果。

## 先记住三个判断层次

能聊天说明请求链路跑通；选出的token相同说明有限输入下生成轨迹一致；完整logits一致还要求逐一比较151936个词表分数。前两个判断不能代替第三个。性能则必须另外使用去诊断版本，在同样工作条件下测请求总时间。

执行计划缓存保存的是如何运行主干的准备结果。新问题的输入计算和KV重置仍要进行。把“非末块省输出层”和“常驻主干计划”一起打开后得到的用时变化，是组合结果，不能全部归给缓存。

## 当前交付程序与历史实验版本

新可选源码profile是`mi11-qwen3-06b-source-plan-v1`，ELF SHA前缀`2cc76982`，库`5b9d239b`，worker源码`bbec5510`。旧可选profile是`mi11-qwen3-06b-plan-v1`，ELF`ee5ed8d6`。两个profile的选择与运行包完整性检查已经接通，但新程序的三题对照和独立CLI三题没有导出完整分数。因此不能把历史51对完整logits写成“新profile51对已验”。

51对完整分数来自诊断ELF`45d8d720`/库`bc708943`；组合性能来自去诊断ELF`559354f6`/库`7d6147a6`；二者worker源码同为`4416471d`。它们与正式聊天worker职责相邻但不是同一份ELF。源码审核和生成回归提供衔接证据，不能抹掉实际运行版本的差别。

## 目前最值得补什么

若下一阶段需要给新profile写数值或速度承诺，应先定义并执行绑定2cc程序的正式验收；现在只承诺已通过的生成与交付链路。其他手机、模型、后端、同实例并发/异步，以及带缓存失败load均未覆盖。公开evidence是白名单派生数据与离线复算，能复算算术和一致性，不能独立证明真实手机运行或完整logits原件。

工程整理细节与全部SHA见审计说明（本地原件：`results/android/acceptance-integration-20261016/evidence-audit-v1/说明.md`）。本页已提供，学习者理解待反馈。

公开版仅列本地原件名称，完整原件不随仓库分发；去除设备原始信息的[派生范围索引](../evidence/acceptance-integration-20261016/scope-index.json)可在源码仓库查看。
