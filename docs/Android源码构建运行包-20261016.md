# 让源码构建真正进入聊天入口

上一阶段分别验证了两件事：运行包可以离开历史构建目录启动，MNN框架也能从固定源码完整重建。现在把它们接起来，让那份已经编译并实机验收的新程序通过正式聊天入口工作。

## 一次启动，各层负责什么

构建器的输入是MNN源码、项目补丁和工具依赖，输出是框架库和手机程序。导出器检查这组构建的验收来源与实际文件，输出一个小型运行目录。客户端读目录里的profile，确定要部署哪份程序，然后手机worker加载模型、接收问题。

profile负责程序选择和身份核对，不参与token计算。提问仍沿消息→Tokenizer→LLM安排prefill/decode→Module/Session/Pipeline→Execution→采样和文字返回。模型权重仍在手机，导出不会把权重重新量化。

新包保存完整源码构建、独立审核和生成回归的身份信息。旧包保存原有构建来源。两者都受到固定配置限制；通过profile选择新程序时，默认聊天入口的旧配置仍可照常使用。

## 在本机使用

本轮已导出的新包位于`build/source-runtime-bundle-20261016/手机运行包 空格`，直接在项目根目录运行：

```powershell
python scripts/android/phone_chat.py --mode full --stats --prefill-plan-cache --plan-profile "build/source-runtime-bundle-20261016/手机运行包 空格/profile.json"
```

支持多轮、/history、/stats、/new与/exit。该模式每轮完整重算消息历史的KV，复用主干执行计划；部署总预算512token，包含输入模板和预留生成数，超限可/new。

如需在本项目保留完整验收材料的环境里重新导出这组固定产物，目标目录必须尚不存在：

```powershell
python scripts/android/phone_plan_profile.py export-source --source-build results/android/clean-source-build-20261015/recipe-v1/link-fix-v1/build.json --output "build/另一个新目录"
```

导出需要固定构建和对应验收原件；运行时只需客户端、运行包、ADB及手机已有模型。包约87.5MiB，不含静态库、NDK或模型权重。本轮只导出了一份包，没有清理旧包或失败原件。

## 这一阶段证明了什么

新的正式CLI从独立客户端目录启动，该目录起初没有build/results/头文件或归档；工作目录就是含中文与空格的运行包。主机Python读取审计禁止历史构建/记录/原脚本的访问，三次请求仍完成，且未调用旧构建解析器。审计只覆盖主机Python读取，不是子进程沙箱。

冷启动长输入、续轮、/new后再次长输入的回答token/文字/状态与上一阶段已验的新程序对应一致，计划状态为首次准备、复用、复用，退出清理确认。旧真实运行包也在新解析器下通过离线验证。

采集器在CLI完成后复制深层日志时遇到Windows长路径限制，原collector退出1保留；41个原件已另以短文件名和映射清单保存，独立逐字节核对，模型没有重跑。客户端和手机程序实际退出均为0。采集过程的失败与推理结果分开记录即可，不必把日志复制实现当成推理原理来学。

新11项测试全过，相关旧38项中37通过、1项真实symlink权限跳过。完整工程记录见[本阶段续做](../evidence/source-runtime-bundle-20261016/README.md)。

## 源码入口与边界

- [phone_plan_profile.py](../scripts/android/phone_plan_profile.py)：`resolve_source_build`核导出前输入，`export_source_bundle`打包，`resolve_profile`在运行时核包内文件。
- [phone_chat_plan.py](../scripts/android/phone_chat_plan.py)：`PlanCacheSession`按profile设置这次实例的程序位置，启动前重核，然后交给原聊天执行链。

希望你学会的是解释“构建输出怎样成为启动输入”，以及为什么换一个目录不应要求把旧静态库也带走。课程已提供，理解待反馈。

当前新增的是固定受验构建的一条显式可选入口。没有完成任意新机器编译产物自动纳入、其他手机/模型适配，也没有新增完整logits或性能结论；下一步是把独立环境准备和统一验收做得清楚。
