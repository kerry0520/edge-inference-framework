# 启动前检查为什么不等于推理验收

这节只引入一个区分：**准备条件满足，与模型实际完成请求，是两个不同的判断。**

你现在输入一句话，电脑先选定运行包，通过ADB找到手机，再由手机程序加载权重、执行prefill/decode并回传文字。任何一步缺东西，最后都可能表现成“没回答”，但解决位置不同。

例如，电脑上缺少ADB时，请求还没到手机；手机上缺少权重时，连接可以成功，模型仍不能加载；即使文件齐全，也必须实际执行请求，才能检验张量计算、输出和退出。因此检查器应回答“问题卡在哪个准备环节”，不能用文件存在证明推理正确。

| 层次 | 输入与职责 | 能证明什么 |
|---|---|---|
| 本地准备 | 当前客户端、profile、包内程序与ADB路径 | 文件身份和本地依赖可用；不需要手机 |
| 设备准备 | ADB连接、固定设备身份、模型文件可读且非空 | 当前时刻能访问目标手机及必要文件；不证明权重内容正确 |
| 请求验收 | 模型实际收到token并完成计算、流式响应、清理 | 这次场景实际执行正常；不自动覆盖所有输入、设备或模型 |

这与nano-vLLM里的“配置检查”和“执行生成”是同一种职责划分。配置检查能发现模型路径错误，却不能替代一次forward。

本项目上一阶段已经完成固定手机上的请求验收。这一阶段补启动前的诊断入口，帮助别人按公开说明准备环境；它不会改变MNN计算公式、量化方式、KV或执行计划。离线检查未连接设备时，设备项必须写“未运行”，不能显示“通过”。

## 使用检查入口

在项目根目录运行，默认只检查电脑，不启动ADB：

```powershell
python scripts/android/phone_runtime_check.py --plan-profile "build/source-runtime-bundle-20261016/手机运行包 空格/profile.json" --output readiness-local.json
```

明确要求检查手机时加上`--device`，并换一个未使用过的记录名：

```powershell
python scripts/android/phone_runtime_check.py --plan-profile "build/source-runtime-bundle-20261016/手机运行包 空格/profile.json" --device --output readiness-phone.json
```

ADB不在项目默认位置或PATH中时，加`--adb-path "实际adb.exe路径"`；多个连接需要明确选择时，加`--serial "实际连接标识"`。已有记录不会被覆盖。离线结果里设备为`not_run`；手机检查通过时，也只证明固定身份、五个必要模型文件可读且非空，不核模型内容，不加载模型，不产生回答。

这里“本地通过”只检查ADB文件路径存在，未执行它；真实设备检查才会执行ADB。因此一个损坏的ADB文件可能通过路径检查，再在设备检查中明确失败。这是检查边界，不应写成电脑全部功能已验证。

## 复核已有请求

另一个入口读取已完成会话的三个原件：session.json、worker-stdout.log与记录实际CLI退出码的JSON。输入位置可以不同，不要求复制完整深层日志目录。

```powershell
python scripts/android/phone_verify_session.py --session "会话目录/session.json" --worker-stdout "会话目录/worker-stdout.log" --cli-command "采集目录/cli-command.json" --output session-review.json
```

它复核当前固定full-plan模式的记录一致性；空请求、错误退出、错误计数、流式字节不一致或清理未确认会失败。默认不支持把拒绝混入成功场景；显式加`--allow-budget-rejections`才验证原生预算拒绝，仍拒绝未确认请求。拒绝的身份、超预算条件、单帧无文字、历史保持和时间顺序都会核对。输入的SHA会写入输出，便于知道具体核的是哪一份记录。

要理解计数的意义：长输入先按32token分块，非末块只执行主干，末块执行完整图；后面的decode也包含在完整图计数中。因此`总forward = full + trunk`，不能再把decode加一次。比如此前三轮是`27 full + 4 trunk = 31`次，其中24次decode已经算在27里。

日志一致不是数学证明：假如某个计算内核稳定算错，计数和退出仍可能全部正常。要判断输出是否正确，需要另做同输入、同配置下的参考结果或数值对照；这个入口不会冒称替代这些工作。

源码入口：[phone_runtime_check.py](../scripts/android/phone_runtime_check.py)负责准备检查，[phone_verify_session.py](../scripts/android/phone_verify_session.py)负责已有会话的离线一致性复核。二者都不进入MNN算子计算。

工程结果：新旧真实运行包的离线检查、独立十模块客户端检查、固定手机只读检查通过；新23项单元测试通过。最终验收器离线复核此前三轮真实请求，并拒绝七份新损坏变体，独立语义检查覆盖EOS、UTF-8拆分和连续历史。本轮没有新增模型请求、编译或运行包大文件复制，也没有新增速度或数值正确性结论。课程已提供，理解待反馈。
