# 可搬移的本地运行包

本阶段将已验收 worker、源码身份和固定配置导出为本地运行包，并把 ADB 路径作为显式输入。搬移后的入口不需要读取原项目的大型静态库和历史构建目录。默认聊天入口保持原样，512 token 部署预算仍包含输入与输出。

运行包需要先在具有已验收构建的本机导出。公开仓库不分发模型和原生可执行文件，也没有完成任意新电脑的完整源码构建。本阶段不新增性能结论。

`requests.json` 仅保存脱敏派生的输入/输出/文字摘要、执行路由、退出和主机读取范围。运行 `python evidence/portable-plan-profile-20261015/verify.py` 可离线复核三组请求摘要相等、冷建/命中路由、forward 计数及退出记录的一致性。它不能独立证明手机身份、真实执行、原始采集完整性或完整 logits；这些依据本地独立验收。

读取保护只观察主机 Python 的文件打开操作，不是子进程沙箱。结果仅限固定 Mi11 / Qwen3-0.6B / MNN CPU 配置；没有其他设备适配或通用性能声称。

原控制分支首次采集时，电脑保存退出日志失败，原session保留`stopped_with_error`；随后只补读已退出进程的原日志，校验远端前后与本地SHA。搬移分支使用修复后的日志读取，两支原生程序相同。公开`collection_verified`表示原件加独立补读已审核，不表示旧采集器没有失败。

另从独立客户端目录（启动前无build/results、九个客户端模块与已验版本相同）用迁移包执行一次真实CLI：40输入、16输出、18forward，CLI/native/launcher均退出0；生成达到16token上限。这条证据只补充客户端目录独立性，未验收其他电脑或手机，未增加性能声称。
