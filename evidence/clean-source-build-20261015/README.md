# 固定源码完整构建与手机回归

本轮从固定MNN提交导出源码，按项目三补丁构造五个已验源码终态，使用显式本地NDKr30/KleidiAI依赖，在空对象目录完整编译565个MNN对象并组成新静态库，再独立链接原聊天worker。565实际ninja对象与565归档成员按名称及重复计数闭环，ARM64 PIE仅需要Android系统库。

第一次编译在ASM临时文件创建处失败，旧部分对象和原件本地保留；单个ASM探针使用owned TEMP/TMP成功后，第二次从全新对象目录完整构建。只复用固定源码和依赖，不复用第一次对象。配方已为默认构建记录独立临时目录。第二次核心编译完成后，worker路径替换还暴露一次脚本错误；修复仅恢复cpp输入参数，审核后重新链接成功，原失败也保留。

固定手机上旧已验worker与新库重链worker各三次请求，输入/输出token摘要、文字摘要、状态和冷建/命中路径对应一致；两进程正常退出。这里提供的是脱敏派生记录，原始编译和设备证据由本地独立审核保管。

运行`python evidence/clean-source-build-20261015/verify.py`可检查仓库源码SHA和派生记录一致性；它不能独立证明真实编译/手机身份/执行过程或完整logits。没有新增性能结论，也未验收其他电脑、手机或模型。默认聊天profile仍指此前已验运行包，新库作为实验候选验证。
